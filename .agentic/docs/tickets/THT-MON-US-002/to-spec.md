# Spec — THT-MON-US-002: Sign-Out Flow

> Generated by `/to-spec` from the grilling session (see `grilling-plan.md` in
> this folder) plus codebase context.

---

## Problem Statement

Currently, clicking the "Sign Out" button in `MonitoringView.vue` only clears the token from Pinia store without notifying the backend, clearing the Vue Query data cache, redirecting cleanly to the login view with user feedback, or handling session expiration / 401 Unauthorized API responses gracefully.

## Solution

Implement a complete, production-grade Sign-Out flow across backend and frontend:
1. **Backend**: Provide a `POST /api/auth/logout` endpoint in Spring Boot to record audit events and validate logout authorization.
2. **Frontend Store & Query Cache**: Enhance `useAuthStore` to notify the backend, wipe client token/username from state and `localStorage`, and purge TanStack Vue Query cache (`queryClient.clear()`).
3. **Axios 401 Interceptor**: Intercept HTTP 401 responses on protected API calls to automatically trigger session logout and redirect unauthenticated users to `/login?expired=true`.
4. **User Feedback**: Redirect the user to `/login` with feedback messages (`"You have been successfully signed out."` or `"Your session has expired. Please log in again."`).
5. **Testing**: Comprehensive unit tests (Spring Boot controller/security tests, Vitest store and view tests) and Playwright E2E coverage for sign-out and session expiry flows.

---

## User Stories

1. **As a supervisor**, I want to click "Sign Out" in the top navigation bar, so that my active session is invalidated and I am securely logged out.
2. **As a supervisor**, I want all cached call monitoring data purged from browser memory when I sign out, so that sensitive customer call records are not visible to unauthorized users.
3. **As a supervisor**, I want to see a confirmation banner on the login page after signing out, so that I know my logout was successful.
4. **As a supervisor**, I want to be automatically redirected to the login page with a session expired message if my token expires or becomes invalid during API requests, so that I am prompted to re-authenticate safely.

## Implementation Decisions

- **Modules built/modified**
  - **Backend**:
    - `AuthController.java`: Add `@PostMapping("/logout")` endpoint.
    - `SecurityConfig.java`: Protect `/api/auth/logout` with Bearer token authentication.
    - `AuthControllerTest.java`: Unit tests verifying logout endpoint behavior.
  - **Frontend**:
    - `stores/auth.js`: Update `logout()` to call backend `/api/auth/logout`, clear Pinia state, clear `localStorage`, and purge `queryClient`.
    - `services/api.js`: Add Axios response interceptor for 401 status to trigger auto logout.
    - `views/MonitoringView.vue`: Wire "Sign Out" button to execute logout and navigate to `/login?signedOut=true`.
    - `views/LoginView.vue`: Display status message banner when `signedOut` or `expired` query parameters exist.
    - `views/__tests__/LoginView.test.js` & `stores/__tests__/auth.test.js`: Vitest tests for sign-out and feedback UI.
    - `e2e/signout.spec.js`: Playwright E2E test covering manual sign-out and auto sign-out on 401.

---

## Out of Scope

- Token blacklisting with Redis distributed store (stateless JWT handling + server audit logging is sufficient for single node deployment scope).
- Multi-device forced session termination.

---

## Testing Strategy

1. **Backend Unit Tests**: Verify `POST /api/auth/logout` returns 200 OK with valid JWT and 401 Unauthorized without JWT.
2. **Frontend Unit Tests (Vitest)**:
   - Test `useAuthStore.logout()` clears state, `localStorage`, and calls `queryClient.clear()`.
   - Test `LoginView.vue` renders signed-out / session expired alert banners based on query parameters.
3. **End-to-End Tests (Playwright)**:
   - Login as `admin`, navigate to `/monitoring`, click "Sign Out", verify redirect to `/login?signedOut=true` and presence of success banner.
   - Verify protected routes (`/monitoring`) cannot be accessed after sign-out.
